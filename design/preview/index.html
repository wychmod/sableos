03 标识方案

仓库现有 docs/images/logo.svg 是一枚折线构成的「S」， 它能读出字形，但读不出行业语义——放在任何 SaaS、任何开发者工具上都不违和，也就等于没有记忆点。 下面是评估结论与重新设计方案。

现状评估

为什么建议替换

  • 语义空缺：折线 S 不承载「Agent / 运行底座 / 交付」任何一层含义
  • 小尺寸不成立：44px 描边下的 S 字怀过窄，16–24px 时糊成一团折线
  • 不可单色化：当前依赖深色底 + 金色描边，在浅色 README 与白底文章里无法直接使用
  • 团聚感缺失：SableOS 的核心主张是「一群 Agent」，单字形天生表达不了「一群」
  • 配色断裂：#332C27 暖灰底与 #F2B441 燃金是很好的资产，应保留并系统化

结论：重新设计，但继承其暖墨底 + 燃金的配色基因。

设计思路

疾行 Prompt：三枚级联 + 收束短横

  • chevron（>）同时是 Prompt 提示符与「向前推进」，一个形状压两层语义
  • 三枚级联取代原来的一枚，把「一群 Agent 并行推进」画进标记本身
  • 近→远透明度阶梯（0.42 / 0.68 / 1.00）制造纵深，暗示队列与并行
  • 右端收束短横对应北极星里「= 一个 Agent / 交付一个结果」，让标记有落点
  • 纯几何 + 圆帽接头，无渐变依赖（渐变仅作可选美化），可无损转单色

参数化生成：design/assets/make-logo.py，改参数即可整体重算全套资产。

方案对照：现状 · 三个备选 · 选定方案

三个备选概念都做出来了再比较。语义直白的方案（A / C）代价是撞脸，B 表意准确但重心失衡。

为什么用「疾行 Prompt」而不是更直观的「底座 + 平台线」

我试过三套语义更直白的方案：双箭头（一群 Agent）、平台线 + 箭头（底座与 Agent）、方块 + 脱出小方块（目录派生）。 直白方案的代价是「看起来像通用 SaaS 图标」——方块脱出尤其容易和其他产品撞脸。 最终选 chevron 级联，是因为它在 16px 下依然成立、天然可单色化，而且 > 这个形状对目标读者（Java 后端工程师） 有本能的 Prompt 联想，语义靠透明度阶梯和收束横补足，而不是靠把含义画全。

04 设计变量（Design Tokens）

不用纯黑也不用冷灰。纯黑显得廉价、冷灰显得像默认主题；暖墨色系（色相约 30°）让画面有纸张与皮革的质感，也更耐看。

字号 · 间距 · 圆角 · 动效

类别取值用法与理由
正文字号16px / 1.65不跟随系统缩放做小字号，技术读者长时间阅读更省力
流式大标题clamp(2.35rem → 4.15rem)移动端不撑破版心，宽屏拿到足够气势，无断点跳变
字重400 / 500 / 600只用三档；中文在 600 以上容易糊，粗体上限压到 600
间距基数4px（--sp-1 → --sp-32）统一节奏，避免出现 13px、18px 这类随手值
区块纵向节奏clamp(4rem → 8rem)长页面靠大留白分节，不靠分割线和色块
圆角6 / 8 / 12 / 16 / 24 / 32小控件 8、卡片 16、大容器 32，形成一致的圆角家族
版心宽度1160px（正文 68ch）宽屏信息密度与可读性的平衡点
动效时长140 / 240 / 520ms统一缓动 cubic-bezier(.22,1,.36,1)，全部可被 reduced-motion 关闭
渐变表面上的对比度是怎么保证的

Hero 与 CTA 用深色渐变做背景，而渐变背景色 computedStyle 读不到，常规对比度检测会误判成白底。 我的做法是先算出渐变「最亮点」——渐变顶端 #1D1815，叠加燃金光晕（13% 不透明）与网格线（2.8% 白） 后合成约 #3F3221，再按这个最不利采样值验证所有前景色：主标题 11.15:1、正文 6.86:1、标语 7.92:1、统计标签 4.83:1，全部达标。 换渐变参数时必须重跑这一步。

技术取向

为什么不用框架

  • 零构建：直接双击 index.html 就能看，无需 npm / 构建链
  • 零依赖：唯一外部请求是 Google Fonts，且失败时自动回退系统字体
  • 好托管：GitHub Pages 直接开箱，不需要 Actions（后续可选加）
  • 易接手：任何人（含 AI agent）改文案不必先学一套工具链
  • 可升级：真需要博客 / 更新日志时，再引入 Astro 等 SSG，CSS 与 assets 可原样迁移
