## User Scenarios & Testing *(mandatory)*

### User Story 1 - 文件读写只能落在获准目录内 (Priority: P1)

运营者把文件白名单配置为只允许工作区目录。Agent 在对话中试图读取或写入工作区之外的文件时，操作在触碰文件之前就被拒绝；工具调用以失败记录进入审计，模型在下一轮看到可读的拒绝原因。位于白名单目录内的读写则照常返回内容或写入结果。

**Why this priority**: 文件是 Agent 最常用、后果最直接的涉外动作；路径穿越也是应用层校验最容易漏的绕过点。先守住这一条，白名单机制才有可信的起点。

**Independent Test**: 配置一个白名单根，分别对根内与根外的路径发起读、写校验；根内放行且真实文件被读写，根外拒绝且文件内容零变化；再用 `..` 序列尝试爬出白名单根，断言仍被拒绝。

**Acceptance Scenarios**:

1. **Given** 文件白名单只包含工作区目录，**When** Agent 读取工作区内的普通文件，**Then** 校验放行并返回文件内容。
2. **Given** 文件白名单只包含工作区目录，**When** Agent 读取工作区外的文件，**Then** 校验拒绝、抛出统一的安全违规异常，且目标文件未被打开。
3. **Given** 文件白名单只包含工作区目录，**When** Agent 用 `工作区/../../outside/secret.txt` 这类路径穿越访问根外文件，**Then** 校验拒绝，路径穿越无法绕过白名单。
4. **Given** 文件白名单只包含工作区目录，**When** Agent 向工作区内写文件，**Then** 校验放行并真实写入；向工作区外写文件则拒绝且目标文件不存在。

---

### User Story 2 - Shell 只能执行获准的可执行文件 (Priority: P2)

运营者把 Shell 白名单配置为只允许 `ls`。Agent 试图执行 `rm` 时，校验在进程启动之前拦下；执行 `ls` 则正常返回标准输出。命令比较只看首 token，精确、大小写敏感；首 token 带前导空白时先去除空白再比较。

**Why this priority**: 命令执行是破坏力最大的涉外动作。它必须在进程启动之前被拦住，而不是启动后再判断。

**Independent Test**: 配置只允许 `ls`，对 `ls`、`rm`、带前导空白的 `ls`、大小写变体分别发起命令校验；断言放行项继续执行、拒绝项进程零启动。

**Acceptance Scenarios**:

1. **Given** Shell 白名单只包含 `ls`，**When** Agent 发起 `ls`，**Then** 校验放行，进程真实启动并返回输出。
2. **Given** Shell 白名单只包含 `ls`，**When** Agent 发起 `rm`，**Then** 校验拒绝、抛出安全违规异常，进程根本没有启动。
3. **Given** Shell 白名单只包含 `ls`，**When** 命令串首 token 带前导空白（如 `"  ls"`），**Then** 去除空白后按 `ls` 放行。
4. **Given** Shell 白名单只包含 `ls`，**When** 命令为首 token 的大小写变体（如 `LS`），**Then** 因精确、大小写敏感比较而拒绝。

---

### User Story 3 - HTTP 请求与通知推送只能发往获准域名 (Priority: P3)

运营者把 HTTP 域名白名单配置为 `*.example.com`。Agent 请求 `https://api.example.com` 时放行并真实发出；请求 `https://evil-example.com` 时被拒绝且请求零发出——形似域名不能借通配符绕过。通知工具向 webhook 推送时复用同一份域名白名单，并且必须先校验、后发送。

**Why this priority**: 出站请求是数据外泄与误触外部系统的入口；通知推送是"往外送"的第二条出口，必须与 `http_get` / `http_post` 共用同一道墙。

**Independent Test**: 配置 `*.example.com`，对子域、形似域名、白名单外域名分别发起校验；用假 webhook 记录请求次数，断言被拒时零请求、放行时恰好一次；通知场景用顺序断言确认校验发生在发送之前。

**Acceptance Scenarios**:

1. **Given** HTTP 白名单为 `*.example.com`，**When** Agent 请求 `https://api.example.com/x`，**Then** 校验放行并真实发出请求。
2. **Given** HTTP 白名单为 `*.example.com`，**When** Agent 请求 `https://evil-example.com/x`，**Then** 校验拒绝、请求零发出（通配符必须带点号边界）。
3. **Given** HTTP 白名单为 `*.example.com`，**When** Agent 请求白名单外的其他域名，**Then** 校验拒绝、请求零发出。
4. **Given** 已注册一个 webhook 通知渠道且其域名在 HTTP 白名单内，**When** Agent 调用通知推送，**Then** 先通过域名校验、再发送 webhook，audit 记录成功。
5. **Given** 通知渠道的域名不在 HTTP 白名单内，**When** Agent 调用通知推送，**Then** 校验先于发送拒绝，webhook 零请求。

### Edge Cases

- 某一类白名单为空列表或配置缺失时，该类动作必须**全部拒绝**（deny-all），而不是"不校验"。
- 文件路径为相对路径时，按当前工作目录解析后再与白名单根比较；白名单根本身是相对路径时也必须先解析为绝对路径，否则合法目标会被误判为越界。
- 目标路径恰好等于白名单根（而非其子路径）时，视为根内并放行。
- 目标路径形如 `工作区-evil/...` 时，不得被 `工作区` 前缀误命中（按路径段比较，不按字符串前缀比较）。
- URL 无法解析、缺少 host 或不是 HTTP(S) 形式时，一律拒绝而非抛实现层异常。
- 通配符模式 `*.example.com` 不命中裸域 `example.com`，也不命中形似域 `evil-example.com`。
- 域名比较不区分大小写（主机名本身大小写不敏感）。
- 校验失败产生的异常信息必须点名被拒目标（路径 / 首 token / host），便于模型理解并自我纠正。
- 校验失败时，真实文件读写、进程启动、HTTP 请求、webhook 发送均不得发生。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供一个与具体隔离实现无关的沙箱抽象，只暴露"校验一个拟执行动作"这一个入口；动作仅由动作类型与目标字符串构成。
- **FR-002**: 动作类型 MUST 固定为四值——文件读、文件写、Shell 命令、HTTP 请求；文件读与文件写 MUST 共用同一份路径白名单。
- **FR-003**: 系统 MUST 提供核心阶段唯一的应用层白名单实现，按动作类型路由到路径、命令、域名三类校验；接口签名 MUST NOT 出现路径、命令、域名、镜像、容器等某一档实现专属概念。
- **FR-004**: 路径校验 MUST 先将目标路径与所有白名单根规范化为绝对路径再比较；目标位于任一白名单根之内（含根本身）则放行，否则拒绝；`..` 路径穿越 MUST NOT 爬出白名单根。
- **FR-005**: 命令校验 MUST 取命令字符串去除前导空白后的首个 token，与命令白名单精确、大小写敏感比对；不在白名单则拒绝。
- **FR-006**: 域名校验 MUST 解析 URL 的 host 后匹配白名单；MUST 支持精确匹配与 `*.example.com` 形式的通配子域；通配 MUST 带点号边界，形似域不得命中；URL 无法解析或没有 host 时 MUST 拒绝。
- **FR-007**: 任一校验不通过时，系统 MUST 抛出统一的安全违规异常，异常信息 MUST 点名被拒目标；放行的情形 MUST 继续执行工具原有 IO，工具方法除校验入口外其余逻辑不变。
- **FR-008**: 文件读写、Shell、HTTP 请求、通知推送四个涉外工具 MUST 在真正执行前调用校验；通知推送的校验 MUST 早于发送；校验不通过时上述真实动作 MUST 零发生。
- **FR-009**: 校验失败 MUST 复用既有的工具执行失败路径收敛：审计记录 `success=false`，`error_message` 保存可读拒绝原因；系统 MUST NOT 为沙箱新增独立审计旁路。
- **FR-010**: 白名单 MUST 来自三项配置：`file.allowed_paths`、`shell.allowed_commands`、`http.allowed_domains`；任一项为空或缺失时该类动作 MUST 全部拒绝；SMTP 端点白名单不在本节范围，配置项保留给扩展阶段的邮件通知实现。

### Key Entities

- **动作（Sandbox Action）**: 一次拟执行的涉外操作，包含动作类型与目标字符串；目标的具体含义由类型决定（路径 / 可执行文件 / URL）。
- **动作类型（Action Type）**: 文件读、文件写、Shell 命令、HTTP 请求四值；文件读写共享路径规则。
- **白名单策略（Whitelist Policy）**: 三类获准目标的集合——文件路径根、命令首 token、域名或通配子域；空集合表示该类全部拒绝。
- **安全违规（Sandbox Violation）**: 校验不通过时抛出的统一失败信号，携带点名目标的拒绝原因，交由既有工具执行失败路径记录。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在白名单回归测试集中，白名单外的文件读写、Shell 命令、HTTP 请求、通知推送 100% 被拒绝，且对应的真实 IO 发生次数为 0。
- **SC-002**: 路径穿越测试集中，使用 `..` 序列尝试爬出白名单根的用例 100% 被拒绝，绕过成功率为 0。
- **SC-003**: 通配符域名测试集中，形似域名（如 `evil-example.com` 对 `*.example.com`）的误放行次数为 0，合法子域的放行率为 100%。
- **SC-004**: 每一类白名单配置为空或缺失时，该类动作的放行次数为 0（deny-all 可验证）。
- **SC-005**: 被拒绝的工具调用 100% 产生审计失败记录，且失败原因可直接读懂并包含被拒目标。
- **SC-006**: 四个涉外工具改造后，其原有测试 100% 保持通过，工具的正常返回结构与行为不变。
- **SC-007**: 用未来最重的隔离实现反向检验时，沙箱抽象无需增加方法即可实现（接口中立性人工评审通过）。

## Assumptions

- 前序节已交付沙箱抽象四件（接口、动作、动作类型、违规异常）与四个涉外工具；本节沿用既有签名与四值，不修改前序公共接口。
- 工具执行层已有失败审计路径，校验异常上抛后由该路径收敛，无需新增审计代码。
- 三项白名单配置键已在运行配置中预留；SMTP 端点配置项继续保留，但核心阶段不读取、不校验。
- 应用层白名单是"劝阻级"防线，防的是模型误操作，不承诺拦住蓄意攻击；容器/microVM 隔离属扩展阶段。
- MCP 子进程、进程内直调等其他暴露面不在本节接线范围；接口抽象已为其保留扩展空间。
- 生产环境只装配白名单实现；临时放行实现仅作为测试替身存在于测试源码。
- 真实模型、真实 webhook 与真实审计表的人工冒烟不在自动化验收范围，按课件"做完怎么验"人工执行。
