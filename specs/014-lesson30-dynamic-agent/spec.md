> **口径声明**：本节课件第五节「实现回写」已明确「以实现为准」，且本仓库 2026-10-31 已就本 feature 与项目方确认：**§5 的实现口径优先于课件前文原始设计**，同时按 §5 记录对《技术方案》§11.3 的偏差（原始设计保留为演进记录）。本 spec 严格按 §5.1~§5.4 编写。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一句话描述就造出一个会自己跑的 Agent (Priority: P1)

运营在管理台点「新建 Agent」，只填两样东西：名字和这句描述——「每天早上九点查北京天气，把穿搭建议发到团队群」。后台按模板脚手架出一个完整的 Agent 目录（`AGENT.md` 正文与 frontmatter、示例 `scripts/`、`REFERENCE.md`、记忆文件位），立即注册进运行时；**全程不重启**，它马上出现在 Agent 列表里，到 cron 点自己跑起来。

**Why this priority**: 这是本节的存在理由。29 节立住了「一个目录 = 一个 Agent」，但入口还停在「登录服务器往目录里放文件、还得重启」。这条路径把「定义一个 Agent」变成一次表单提交。

**Independent Test**: 在临时工作区调一次创建接口，磁盘上出现完整 Agent 目录、`AGENT.md` 能被既有派生器解析、注册表里立刻可查；带定时声明的即刻进入调度器。不依赖真实模型（创建走模板，不走 LLM）。

**Acceptance Scenarios**:

1. **Given** 工作区里没有该名字的 Agent，**When** 提交「名字 + 描述」，**Then** 返回 200 与该 Agent 的详情，磁盘出现 `agents/<name>/AGENT.md`（另含 `scripts/`、`REFERENCE.md`），且不重启即可在列表与详情接口查到它。
2. **Given** 创建出来的 Agent 声明了定时，**When** 创建成功，**Then** 该项已交给调度器持有触发句柄。
3. **Given** 同名 Agent 已存在，**When** 再次提交同名创建，**Then** 返回 400 并说明「已存在」，且**一个文件都不写**。
4. **Given** 创建过程中派生/注册失败，**When** 失败返回，**Then** 已写出的目录被回滚删除，注册表与调度器里都没有它的残留。
5. **Given** 用户提供了不合法名字（含路径分隔符、`.`/`..`、空白、超长），**When** 提交创建，**Then** 返回 400 点名原因，不创建任何目录。

### User Story 2 - 手工丢一个目录也即上线，删掉即下线 (Priority: P1)

运维不走 API：`scp` 一个 Agent 目录进 `agents/`，几秒内它就被登记、可用；改它的 `AGENT.md`，改完即生效；把目录删掉（或移走），它就从列表消失、定时也停。**行为与 API 建的完全一致**——两条录入路径殊途同归。

**Why this priority**: 「动态管理」的本质是「改目录即改运行时」。没有实时监听，「上传即上线」就名不副实，而且手工维护（git pull、编辑器）是管理员最常用的路径。

**Independent Test**: 在临时目录起一次监听，往 `agents/` 拷贝一个合法 Agent 目录 → 注册表出现它；删除该目录 → 注册表里消失且其定时句柄被取消；放一个坏目录 → 只留一条点名告警，监听线程与其余 Agent 不受影响。

**Acceptance Scenarios**:

1. **Given** 服务已启动且监听就绪，**When** 往 `agents/` 新增一个合法 Agent 目录，**Then** 无需重启即可在 Agent 列表里查到它。
2. **Given** 已注册的 Agent 目录被手工删除，**When** 监听收到删除事件，**Then** 该 Agent 从注册表移除、其定时触发句柄被取消。
3. **Given** 已注册 Agent 的 `AGENT.md` 被就地修改，**When** 监听收到变更事件，**Then** 新定义生效，且旧定时句柄被注销后按新定义重注册（同一任务不会双跑）。
4. **Given** 丢进一个坏目录（缺 `AGENT.md` / YAML 破损 / name 与目录名不符），**When** 监听处理该事件，**Then** 只记录一条点名告警并跳过，监听继续工作、其余 Agent 不受影响。
5. **Given** 启动时 `agents/` 里已有 N 个 Agent，**When** 服务启动完成，**Then** 启动扫描与实时监听并存，不重复注册、不丢 Agent。

---

### User Story 3 - 管理台看得到、改得动、删得掉一个 Agent (Priority: P2)

管理台的「Agent」页列出全部 Agent；点进详情是一个五页签的抽屉：基本信息（名字/描述/provider/model/工具/定时）、生成（用大模型按描述出文件草稿，逐个文件可改）、文件（左侧文件树、右侧可编辑并保存）、会话（这个 Agent 的固定管理台会话，直接聊）、记忆（这个 Agent 自己的长期记忆，只读）。删除前二次确认，删完在归档目录里还能找到它。

**Why this priority**: 26 节的管理台「能看不能管」。接口齐了但没有页面，运营仍然摸不到；这一页是本节对外的最终形态。

**Independent Test**: 走一遍「新建 → 详情五个页签各打开一次 → 在文件页改一行保存 → 在会话页发一句话 → 删除」，每步都命中对应接口且界面有可读反馈；改完的 `AGENT.md` 立即生效。

**Acceptance Scenarios**:

1. **Given** 有 N 个 Agent，**When** 打开 Agent 页，**Then** 列出 N 行，每行可取详情、可删除（删除前二次确认）。
2. **Given** 在文件页编辑 `agents/<name>/AGENT.md` 并保存，**When** 保存成功，**Then** 该 Agent 按新定义重注册（定时变更时旧句柄先注销），界面提示已生效。
3. **Given** 在会话页输入一句话发送，**When** 处理完成，**Then** 这条消息落进该 Agent 的固定会话并在气泡里显示答复。
4. **Given** 删除一个 Agent，**When** 确认删除，**Then** 它从列表消失，目录出现在 `archive/` 下，其历史调用审计仍可查。

---

### User Story 4 - 记忆跟着 Agent 走 (Priority: P2)

每个 Agent 有自己的 `MEMORY.md`，就在它自己的目录里，跟 `AGENT.md`、`skills/` 同处一室。管理台「记忆」页签看到的就是这个文件的内容。A 记住的偏好不会被 B 读到。

**Why this priority**: 原设计记忆是全局一份，多 Agent 并存时会互相污染；「Agent 的成长记录」在语义上必须随 Agent 存在与归档。这条是管理台五页签能成立的前提。

**Independent Test**: 让两个 Agent 分别写入记忆，断言两个文件互不相同、互不可见；对无 Agent 上下文的旧调用路径仍能正常工作（回退全局路径，不抛错）。

**Acceptance Scenarios**:

1. **Given** 某 Agent 执行了写入记忆的动作，**When** 查看它的记忆页，**Then** 看到的是它自己目录下 `MEMORY.md` 的内容。
2. **Given** 两个 Agent 各自写过记忆，**When** 分别查询，**Then** 各自只看到自己的条目。
3. **Given** 一个不带 Agent 上下文的旧调用路径，**When** 读写记忆，**Then** 回退到全局路径，行为与改动前一致、不抛异常。

---

### User Story 5 - 文件浏览器能安全地读、按需地写工作区 (Priority: P3)

运维想在页面上「钻进」一个 Agent 目录看它的 `AGENT.md`、脚本、子指令，也想就地改一个文件。工作区接口只暴露 `agents/` 与 `archive/` 两棵子树；任何试图跳到工作区之外的路径一律拒绝，并把原因说清楚。

**Why this priority**: 只读阅读是排障的主要手段，可编辑是「不动服务器改配置」的最后一公里。安全（防目录穿越）是它唯一的硬要点，因此必须独立可验。

**Independent Test**: 目录树接口返回 `agents/` 与 `archive/` 结构；读一个正常文件拿到内容；把 `../../etc/passwd`、绝对路径、编码过的穿越串逐个打进去，全部 400 且不泄露目标内容。

**Acceptance Scenarios**:

1. **Given** 工作区里有若干 Agent 与归档目录，**When** 请求目录树，**Then** 返回 `agents/`（每个 Agent 一个目录，含其内部文件）与 `archive/` 的结构。
2. **Given** 一个位于 `agents/` 内的普通文本文件路径，**When** 请求读文件，**Then** 返回其文本内容。
3. **Given** 一个越界路径（`../` 跳出、绝对路径、指向工作区外），**When** 请求读或写，**Then** 返回 400 点名「路径越界」，不读取也不写出任何工作区外内容。
4. **Given** 通过写接口修改某个 Agent 的 `AGENT.md`，**When** 写入成功，**Then** 走与「更新 Agent」相同的校验与重注册链路（非法定义 400 且不写坏目录）。

---

### Edge Cases

- **创建时目录已存在但未注册**（历史上被删索引留下的孤儿目录）：创建必须以「注册表是否已有该名」为判据拒绝，不得覆盖磁盘上已有目录。
- **监听事件抖动**：编辑器保存常产生多次 MODIFY；重复事件必须幂等——同一定时任务不得出现两个句柄同时触发。
- **创建成功但定时登记部分失败**：定时登记按既有语义逐条跳过并记日志；已成功注册的 Agent 保持可用，不回滚（与 29 节「坏定时不废 Agent」一致）。
- **Agent 目录被移到 `archive/`**：不得被当成「新增 Agent」重新注册（归档不是活动区）。
- **文件名大小写不敏感的文件系统**（Windows/macOS）：`agent.md` 与 `AGENT.md` 视为同一文件。
- **工作区根不存在**：监听启动失败只告警、不阻断服务启动；后续创建仍可工作。
- **一句话生成用的模型未配置**：返回 503 可读原因，不向模型端点发送空模型名。
- **模型返回的内容不是合法定义**：返回 400 可读原因，前端能原样展示，不落盘。

## Requirements *(mandatory)*

### Functional Requirements

**创建与生命周期（US1）**

- **FR-001**: 系统 MUST 提供「创建 Agent」入口，入参只有名字与描述；系统按模板生成完整 Agent 目录（定义文件 + 示例脚本目录 + 参考资料 + 记忆文件位），不依赖模型输出。
- **FR-002**: 创建 MUST 在注册表已有同名 Agent 时第一步即拒绝（400），且不写任何文件。
- **FR-003**: 创建 MUST 在派生或注册中途失败时回滚已写出的目录，不得留下半个 Agent。
- **FR-004**: 创建 MUST 校验名字合法性（非空、不含路径分隔符与 `.`/`..`、长度上限），非法即 400 点名原因。
- **FR-005**: 系统 MUST 提供查询（列表 / 单个）、更新（覆写定义）、删除（注销定时 → 移出索引 → 归档）三组能力。
- **FR-006**: 删除 MUST 按「先注销定时 → 再移出索引 → 最后归档目录」的顺序执行；归档为移动而非物理删除，归档后可追溯。
- **FR-007**: 更新 MUST 在定时声明发生变化时先注销旧句柄、再按新定义注册。
- **FR-008**: 已存在的无状态调用入口 MUST 保持不变。

**两条录入路径（US2）**

- **FR-009**: 系统 MUST 实时监听 Agent 目录根，新增/修改/删除都能在无需重启的情况下反映到运行时。
- **FR-010**: 实时监听的登记动作 MUST 与创建接口的登记动作是同一段代码（同一个登记入口）。
- **FR-011**: 监听 MUST 在单个目录处理失败时只记录点名告警并继续，不拖垮监听线程、不影响其他 Agent。
- **FR-012**: 启动扫描与实时监听 MUST 并存：启动已登记的 Agent 不得因监听启动而重复登记或丢失。
- **FR-013**: 监听与调度 MUST NOT 把异步编程模型引入请求链路（守护线程属基础设施，同 25 节调度线程同类）。

**生成与保存（US3、US5）**

- **FR-014**: 系统 MUST 提供「按描述生成文件草稿」能力：一次模型调用产出该 Agent 的一组文件，先校验定义可解析，再返回给前端预览；**不落盘、不注册**。
- **FR-015**: 生成 MUST 在模型输出不可解析时返回 400 可读原因；生成使用的模型未配置时返回 503 可读原因。
- **FR-016**: 生成与保存都 MUST 走既有的模型调用出口并落 `llm_calls` 审计（原则五）。
- **FR-017**: 系统 MUST 提供「保存一组文件」能力：先校验定义可解析（非法 400、不写坏目录）→ 写入 → 重注册（定时变更先注销旧句柄）。
- **FR-018**: 生成草稿时若目标 Agent 已存在，MUST 沿用其现有 provider，保证生成结果仍可运行。

**工作区浏览（US5）**

- **FR-019**: 系统 MUST 提供目录树查询，覆盖 `agents/` 与 `archive/` 两棵子树。
- **FR-020**: 系统 MUST 提供读文件能力，返回文本内容。
- **FR-021**: 系统 MUST 提供写文件能力。
- **FR-022**: 工作区读写 MUST 做目录穿越防护：解析为绝对路径并归一后必须落在工作区根内，否则 400 点名「越界」，且不得读/写工作区外任何内容。
- **FR-023**: 写 `agents/<name>/AGENT.md` MUST 走「更新 Agent」链路（校验 + 重注册），不得直接裸写盘。

**每个 Agent 的记忆（US4）**

- **FR-024**: 默认记忆后端 MUST 把记忆存到该 Agent 自己的目录下（`agents/<name>/MEMORY.md`），与管理台「记忆」页签一致。
- **FR-025**: 工具执行路径 MUST 能知道「正在替哪个 Agent 执行」，据此把记忆落到该 Agent；读路径 MUST 同样按 Agent 定位。
- **FR-026**: 无 Agent 上下文的旧调用 MUST 回退到原全局路径，行为向后兼容，不抛异常。
- **FR-027**: 系统 MUST 提供「查某 Agent 记忆」的入口；全局记忆查询入口按 §5.2.1 移除。

**固定会话（US3）**

- **FR-028**: 每个 Agent MUST 有一条固定的管理台会话（同三元组幂等），可查询其内容、可向其发消息并触发处理。
- **FR-029**: 固定会话的身份拼接 MUST 仍只由既有的单一公式生成，不得另起拼装。

**对外契约（全节）**

- **FR-030**: 本节所有 HTTP 端点 MUST 复用既有统一响应信封与全局异常翻译；错误码沿用既有口径（400 参数/定义非法、404 不存在、503 生成模型未配置、504 超时），不发明新状态码。
- **FR-031**: 对外端点清单 MUST 与课件 §5.3 的最终端点全表逐条一致（13 条）。
- **FR-032**: 管理台 MUST 交付「Agent 列表 + 详情五页签（基本信息 / 生成 / 文件 / 会话 / 记忆）」，构建产物入库并与源码一致。

### Key Entities

- **Agent 定义目录**：一个子目录一个 Agent；含定义文件（frontmatter = 运行配置、正文 = 任务指令）、可选脚本/参考资料/绑定子指令、以及该 Agent 的记忆文件。
- **Agent 派生视图**：由定义目录派生出的运行配置，是全系统（模型调用、工具、定时、记忆）共用的唯一运行声明。
- **Agent 公开视图**：对外暴露的 Agent 元信息（名字、描述、provider、model、工具、渠道、定时），不含系统提示词等内部指令。
- **文件节点**：目录树中的一项（名称、相对路径、是否目录、子节点）。
- **归档区**：被删除 Agent 目录的归宿，只读可查、不参与运行。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 从提交「名字 + 描述」到该 Agent 出现在列表并可调用，不重启进程，全流程在一个请求内完成。
- **SC-002**: 手工往目录根丢一个合法 Agent 目录后，无需重启即可在列表查到（判据是监听链路可达，不是固定秒数）。
- **SC-003**: 创建同名 Agent 时磁盘零新增文件（按目录快照比对）。
- **SC-004**: 创建中途失败的用例中，失败后注册表与调度器均无该 Agent 残留、目录被清除。
- **SC-005**: 越界路径（相对跳出 / 绝对路径 / 编码穿越）100% 被拒（400），且响应中不含目标文件内容。
- **SC-006**: 删除一个 Agent 后，其目录存在于归档区、注册表与调度器均无该条目。
- **SC-007**: 两个 Agent 的记忆内容互不可见；同一 Agent 的多个会话共享其自己的记忆。
- **SC-008**: 全部既有测试用例保持通过，`mvn clean verify` 全绿（含格式、编码规约、静态安全检查）。
- **SC-009**: 管理台从构建产物启动后，五个页签各能完成一次真实读写（不是空壳）。

## Assumptions

- 承接 29 节交付：目录派生、运行时注册/注销、定时注册与句柄表均已就位，本节只做编排与对外暴露，不重写这些能力。
- 认证鉴权、带脚本的 zip/multipart 上传、Agent 启停状态位、创建时 dry-run 试跑、版本历史、多轮追问式生成，**本版不做**（课件 §三「先别做」），留扩展阶段。
- 生成用的 provider/model 通过新增的配置键指定：provider 缺省取已登记清单第一个，model 留空则生成端点明确 503。
- 工作区根沿用既有可覆盖配置（默认 `.sableos`），监听与接口都基于同一解析结果。
- 前端构建不在 Maven 生命周期内，交付时需手工构建并把产物入库。
