# Feature Specification: Web Service——把内部能力包装成对外 REST API 的门面

**Feature Branch**: `010-lesson26-web-service`

**Created**: 2026-10-29

**Status**: Implemented (2026-10-29)

**Input**: User description: "第26节需求：Web Service——把 SableOS 内部能力包装成对外 REST API 的门面。只做后端；管理平台前端与前端风格 skill 不在本次范围。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 业务系统通过 HTTP 与 Agent 连续对话 (Priority: P1)

业务系统先创建一个会话，拿到会话标识；此后每轮把用户消息发到该会话，拿到 Agent 的最终答复。同一会话的历史在多次请求之间连续累积，与终端里 `sableos chat` 产生的历史落在同一份存储里。

**Why this priority**: 这是 Web Service 存在的最直接理由——没有它，业务系统只能隔着终端或自己调模型，SableOS 无法成为企业流程的一部分。

**Independent Test**: 用 HTTP 客户端建会话 → 发消息 → 查历史，断言三步都返回统一成功信封，历史包含刚发的用户消息与 Agent 答复；同一组身份重复建会话拿到同一个会话标识。

**Acceptance Scenarios**:

1. **Given** 系统已启动且至少有一个可用 Agent，**When** 调用方以 `profile` 建会话，**Then** 返回统一的成功信封与会话标识，标识由「渠道 + 用户 + Agent」三元组稳定生成。
2. **Given** 一个已存在的会话，**When** 调用方发送一条不超过大小上限的消息，**Then** 返回 Agent 的最终答复，且该会话历史同时追加用户消息、模型输出与（如有）工具结果。
3. **Given** 同一三元组已经建过会话，**When** 再次建会话，**Then** 返回同一个会话标识与既有历史，不产生第二条会话。
4. **Given** 消息超过大小上限，**When** 调用方发送，**Then** 返回 400 且不调用 Agent。
5. **Given** 会话标识不存在，**When** 调用方发消息或查历史，**Then** 返回 404 且指名缺失的会话。

---

### User Story 2 - 业务系统一次性调用 Agent (Priority: P2)

业务系统不需要保留对话上下文，只想把一个任务丢给某个 Agent 并拿到答复。调用方按 Agent 名发起一次调用，系统用一次性的会话承载该次处理，跑完返回答复。

**Why this priority**: 短任务同步调用是集成场景里最常用的形态，也是 Webhook 触发、跨语言集成的基础。

**Independent Test**: 对已注册 Agent 发起一次调用，断言答复非空；对未注册 Agent 发起调用，断言 404 且不进入处理链；两次调用使用不同的临时会话，历史互不串扰。

**Acceptance Scenarios**:

1. **Given** 一个已注册的 Agent，**When** 调用方发起无状态调用，**Then** 返回该 Agent 的最终答复。
2. **Given** 一个不存在的 Agent 名，**When** 调用方发起无状态调用，**Then** 返回 404。
3. **Given** 同一调用方连续发起两次无状态调用，**When** 两次都完成，**Then** 两次各自拥有独立的临时会话，不共享对话历史。

---

### User Story 3 - 集成方查询底座状态与资源 (Priority: P3)

运维或集成方需要在不触发模型调用的情况下看清底座：有哪些 Agent、有哪些工具、某个 Agent 的长期记忆写了什么、当前系统版本与各模型提供方是否连得上。外部监控还可以用一个轻量存活端点做探针。

**Why this priority**: 这些只读查询让对接方可以自解释、自诊断，也是管理平台前端后续渲染页面的数据来源。

**Independent Test**: 逐个调用查询端点，断言都返回统一信封；在没有任何模型调用的前提下，Agent 清单、工具清单、记忆全文、系统信息与 Provider 连通状态都能拿到；存活端点返回成功。

**Acceptance Scenarios**:

1. **Given** 已加载若干 Agent，**When** 查询 Agent 清单，**Then** 返回每个 Agent 的名称、描述、所用提供方与模型等可公开信息。
2. **Given** 已注册若干工具，**When** 查询工具清单，**Then** 返回每个工具的名称、描述与入参约定。
3. **Given** 某个 Agent 已写入长期记忆，**When** 按该 Agent 名查询记忆全文，**Then** 返回可读内容；未指定 Agent 名时按默认 Agent 查询。
4. **Given** 系统配置了若干模型提供方，**When** 查询系统信息，**Then** 返回应用标识、版本与每个提供方的实时连通状态。
5. **Given** 任意时刻，**When** 调用存活端点，**Then** 立即返回成功，不依赖数据库之外的外部服务。

---

### Edge Cases

- 建会话时 `profile` 缺失或为空白 → 400，且不创建会话。
- 建会话时引用的 Agent 未注册 → 404。
- 发消息内容为 `null` 或空白 → 400。
- 消息大小恰好等于上限 → 放行；超过 1 个字符 → 400。
- 查历史时历史超过条数上限 → 只返回最近的部分，不报错。
- 归档不存在的会话 → 404；归档已归档的会话 → 幂等成功，不报错。
- 归档后查历史 → 仍能查到（软归档，行保留）。
- Agent 处理超过 60 秒 → 504，且对外不暴露内部异常细节。
- 模型提供方不可达 → 503，统一话术不泄漏连接串、密钥等内部信息。
- 未预期的内部异常 → 500，响应体只给统一话术，细节只进日志。
- 系统未配置任何 Provider 或 Agent → 所有查询端点仍可正常返回空清单，不启动失败。
- 系统信息探测某个 Provider 超时 → 该条标为不可达，其它条与整体请求不受影响。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供六个按资源划分的对外入口分组，共 10 个端点；路径与动词固定为：`POST /api/v1/sessions`、`POST /api/v1/sessions/{id}/messages`、`GET /api/v1/sessions/{id}`、`DELETE /api/v1/sessions/{id}`、`POST /api/v1/agents/{name}/invoke`、`GET /api/v1/profiles`、`GET /api/v1/memory`、`GET /api/v1/tools`、`GET /api/v1/health`、`GET /api/v1/info`。
- **FR-002**: 对外入口 MUST 只承担参数校验、响应包装与错误处理；发消息与无状态调用 MUST 委托给与命令行入口相同的统一处理入口，不得在入口内另起处理链。
- **FR-003**: 发消息 MUST 校验消息大小，单条消息上限 32KB；超过上限返回 400，会话不存在返回 404。
- **FR-004**: 查历史 MUST 返回该会话最近最多 100 条往来记录；会话不存在返回 404。
- **FR-005**: 归档 MUST 采用软归档：会话状态置为 `archived` 并记录归档时间，物理行保留；归档后查历史仍可返回内容；归档不存在的会话返回 404，重复归档幂等成功。
- **FR-006**: 建会话 MUST 固定渠道为 `web`；请求体 `profile` 必填、`userId` 可选（缺省 `anonymous`）；同一「渠道 + 用户 + Agent」三元组重复创建 MUST 返回同一个会话，标识只允许由会话身份的唯一生成处拼接。
- **FR-007**: 无状态调用 MUST 使用一次性会话承载该次处理；Agent 未注册返回 404。
- **FR-008**: 所有端点 MUST 使用统一的响应信封（成功与错误同形，含状态码语义字段、消息、数据、时间戳与链路标识）。错误状态码固定为：400 参数错误、404 资源不存在、500 内部错误、503 模型提供方故障、504 Agent 调用超时。
- **FR-009**: Agent 调用 MUST 有 60 秒上限；超时返回 504。超时后释放请求线程，允许底层调用在后台自行收尾，但不得阻塞或拖垮其它请求。
- **FR-010**: 系统 MUST 拒绝在 500 响应中回显内部异常消息；内部细节只写日志。503 与 504 的消息也 MUST 为可对外的话术。
- **FR-011**: 查询 Agent 清单 MUST 返回 Agent 名称、描述、提供方名与模型等可公开字段，不得返回系统提示词等内部指令文本。
- **FR-012**: 查询工具清单 MUST 返回工具名称、描述与入参约定。
- **FR-013**: 查询记忆全文 MUST 支持可选 Agent 名参数，缺省取默认 Agent；未写入过记忆时返回空内容而非错误。
- **FR-014**: 查询系统信息 MUST 返回应用标识、版本，以及每个已配置模型提供方的实时连通状态（可达 / 不可达、耗时、失败原因）；探测 MUST 有短超时，单个提供方失败不得影响其它条目与整体响应。
- **FR-015**: 存活端点 MUST 不依赖模型提供方或任何外部服务，立即返回成功。
- **FR-016**: HTTP 层 MUST 使用 Java 21 虚拟线程承载请求，保持同步阻塞式编程模型；MUST NOT 引入响应式栈、自建线程池或异步编排框架。
- **FR-017**: 系统 MUST 自动生成并对外暴露接口文档（接口清单与数据形状可自助查看）。
- **FR-018**: 核心阶段 MUST 对 `/api/**` 开放所有来源的跨域请求；不得把该放宽策略扩展到非 API 路径。
- **FR-019**: 所有用户可控字符串在写入日志前 MUST 做换行净化；密钥等凭证 MUST NOT 出现在任何响应或日志中。
- **FR-020**: 本节 MUST 只交付后端；管理平台前端、静态资源托管、单页应用路径回落与前端风格资产均不在范围内。

### Key Entities

- **会话（Session）**：由「渠道 + 用户 + Agent」三元组唯一确定；包含 Agent 名、渠道、用户标识、状态（`active` / `archived`）、创建时间、最后活跃时间、归档时间与按序的往来记录。
- **往来记录（Session Message）**：角色（用户 / 模型 / 工具）、文本内容、（模型的）工具调用请求、工具名与工具成败；同一会话内只增不减。
- **Agent 视图（Profile View）**：Agent 名称、描述、所用提供方与模型、可用工具名、可选渠道等；不暴露系统提示词。
- **工具视图（Tool View）**：工具名称、描述、入参约定。
- **提供方状态（Provider Status）**：提供方名称、类型、是否可达、探测耗时、失败原因（可为空）。
- **系统信息（System Info）**：应用标识、应用版本、提供方状态清单。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 集成方可以在 10 分钟内用 HTTP 客户端完成「建会话 → 发消息 → 查历史 → 归档」全流程，无需阅读源码。
- **SC-002**: 10 个端点在带真实模型的联调环境中逐条走通，失败时返回的错误状态码与约定完全一致。
- **SC-003**: 终端里产生的会话可以通过对外接口按标识查到，两个入口看到同一份历史，差异为 0 条。
- **SC-004**: 在模型提供方被切断的情况下，调用方在 60 秒内收到 503 或 504，而不是无限等待；任何 5xx 响应都不包含内部连接串、密钥或异常堆栈。
- **SC-005**: 200 个并发调用在同一实例上完成，不出现请求线程饥饿或相互阻塞，存活端点在压测期间始终可响应。
- **SC-006**: 未配置任何模型提供方或 Agent 的干净环境可以直接启动服务，所有只读端点返回空清单而不是启动失败。
- **SC-007**: 接口文档页面可直接打开，10 个端点与其请求/响应形状齐全，无需手写文档。

## Assumptions

- **A-001（已确认）**：`GET /api/v1/memory` 的 `profile` 参数可选，缺省取 `default`；返回该 Agent 的长期记忆全文，未写入时返回空内容。
- **A-002（已确认）**：`GET /api/v1/info` 的 Provider 状态采用实时连通探测（短超时，不发起模型推理、不消耗 token）；探测失败只标记该条不可达。
- **A-003（已确认）**：`DELETE /api/v1/sessions/{id}` 为软归档，`status` 置 `archived`、写 `archived_at`，行保留，归档后查历史仍可查到。
- **A-004（已确认）**：`POST /api/v1/sessions` 请求体 `profile` 必填、`userId` 可选（缺省 `anonymous`），渠道固定 `web`。
- **A-005**：部署形态为内网单实例，本节不做认证、授权、限流与多租户；生产暴露面由部署方式（回环绑定或认证反向代理）兜底。
- **A-006**：核心阶段「定义一个 Agent」仍以手写 Agent 目录为准；通过接口创建/修改 Agent 归后续章节。
- **A-007**：会话历史按「最近 N 条」返回，按时间正序排列，便于调用方直接渲染。
- **A-008**：经本地依赖核实，当前运行时不包含 OpenAI 自动装配，课件中「排除 OpenAI 自动装配」的启动坑在本仓库不复现；不会照抄该排除项（排除不存在的自动配置类会导致启动失败）。DashScope 已由既有开关关闭。

## Dependencies

- 复用既有的统一处理入口、会话身份与持久化、Agent 注册表、工具注册表、长期记忆门面、模型提供方清单与审计链路。
- 依赖第 16～25 节已交付的运行时组件；本节不新增数据表、不改动既有表结构。
- 管理平台前端由独立 agent 基于本节接口另行实现，不在本 spec 的交付与验收范围内。
