# Feature Specification: Sandbox 白名单管理接口（增删改查）

**Feature Branch**: `008-sandbox-whitelist-admin`

**Created**: 2026-10-29

**Status**: Draft

**Input**: User description: "把 docs/requirements/Sandbox白名单管理接口设计.md 落成可实施的 feature —— 为第 24 节的白名单提供运行时增删改查，改动立即生效、持久化重启仍在、跨平台一致可验证。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 运营方运行时增删白名单条目并立即生效 (Priority: P1)

运营方原本只会改 `application.yaml` 再重启进程才能调整沙箱白名单。现在他通过管理接口新增一条目录白名单，不重启进程，Agent 下一次工具调用就能读写该目录；删除该条目后，同一动作立即被拒绝。

**Why this priority**: 这是本 feature 的全部价值主张——「运行时增删 + 立即生效」。没有这一条，其余一切都只是持久化细节。它同时验证了快照刷新通道（配置 → 校验路径）是否打通。

**Independent Test**: 在一个运行中的实例上新增一条文件目录白名单，用工具真实读写该目录内文件（成功）；删除后重试同一动作（被拒绝且出现统一的安全违规异常）。全程不重启进程。

**Acceptance Scenarios**:

1. **Given** 白名单为空（deny-all），**When** 运营方新增一条目录条目，**Then** 对目录内文件的读写校验立即放行，无需重启。
2. **Given** 某目录已在白名单内，**When** 运营方删除该条目，**Then** 对同一目录的读写校验立即被拒绝。
3. **Given** 运营方修改某条目的值，**When** 保存成功，**Then** 新值立即生效、旧值立即失效。

---

### User Story 2 - 条目持久化，重启后仍生效 (Priority: P1)

运营方在生产环境调整完白名单后重启进程，之前通过接口维护的条目全部还在，运行时策略从持久化存储恢复，不退回配置文件里的旧值。

**Why this priority**: 与 US1 同级。如果重启后条目丢失，"运行时管理"在生产上不可用——运维不可能每次重启都重新手工录一遍。

**Independent Test**: 新增若干条目后停止进程并重新启动，查询列表确认条目仍在；用工具验证这些条目对应的动作仍被放行。

**Acceptance Scenarios**:

1. **Given** 通过接口新增了条目，**When** 进程重启，**Then** 条目仍在且运行时策略与之相符。
2. **Given** 运营方删光了所有条目，**When** 进程重启，**Then** 配置文件里的条目**不会**被重新写回，白名单仍为空（deny-all）。
3. **Given** 从未通过接口改过白名单的既有部署，**When** 首次升级到本版本并启动，**Then** 配置文件里的三类白名单被导入为初始条目，行为与升级前一致。

---

### User Story 3 - 白名单条目的查询与详情 (Priority: P2)

运营方打开管理台或直接调用接口，看到当前生效的所有白名单条目，可按类型筛选，并查看每条的值、说明与创建/更新时间，用于审计与排障。

**Why this priority**: 可读性是"可审计"定位的必要条件，但它不改变运行时行为，因此排在 P2。

**Independent Test**: 预置三类条目各若干，按类型筛选查询，确认只返回该类型且按稳定顺序排列；再按标识查询单条，字段完整。

**Acceptance Scenarios**:

1. **Given** 库中有三种类型的条目，**When** 运营方不带筛选条件查询，**Then** 返回全部条目并按「类型、值」稳定排序。
2. **Given** 库中有三种类型的条目，**When** 运营方按某一类型查询，**Then** 只返回该类型的条目。
3. **Given** 某条目存在，**When** 运营方按标识查询，**Then** 返回该条目的完整信息。
4. **Given** 某标识不存在，**When** 运营方按标识查询，**Then** 返回"不存在"错误而非空结果。

---

### User Story 4 - 条目值的统一校验与判重 (Priority: P2)

运营方录入路径、命令、域名时，系统按类型做格式校验与归一，非法值被明确拒绝并说明违反了哪条规则；等价写法不会被记成多条重复条目。

**Why this priority**: 没有校验，白名单会积累脏数据，而脏数据的后果是"存了但永远不生效"。它与 US1/US2 同期可用，但属于防御性能力，故列 P2。

**Independent Test**: 对三类值分别提交合法与非法输入，确认非法输入被拒且错误信息说明规则；对同一路径的五种等价写法依次提交，确认第二次起被判为重复。

**Acceptance Scenarios**:

1. **Given** 类型为域名，**When** 运营方提交含协议、端口、路径或非 ASCII 字符的值，**Then** 请求被拒绝并提示只接受主机名形式。
2. **Given** 类型为文件路径，**When** 运营方依次提交同一目录的等价写法（多余分隔符、`.`、`..` 回溯、末尾分隔符），**Then** 第二次起被判为重复条目。
3. **Given** 任意类型，**When** 运营方提交空值或超长值，**Then** 请求被拒绝。
4. **Given** 重复提交已存在的条目，**When** 系统识别到冲突，**Then** 返回冲突错误而不是静默覆盖或静默成功。

---

### User Story 5 - 管理接口的开关与安全提示 (Priority: P3)

运维意识到管理接口等价于 root 权限（能加"允许任意目录 + 允许解释器"）。他可以通过一个配置项关闭该接口；接口启用时，进程启动会明确告警，提醒只绑定回环地址或置于认证代理之后。

**Why this priority**: 产品决策是默认开启，因此"可关闭 + 有告警"是必要的安全兜底；但它不产出新能力，排 P3。

**Independent Test**: 默认配置启动，日志中出现明确的启用告警；把开关设为关闭后重启，访问管理路径返回"资源不存在"。

**Acceptance Scenarios**:

1. **Given** 开关为默认值（开启），**When** 进程启动，**Then** 日志中出现"管理接口已启用、等价 root、须限制访问来源"的告警。
2. **Given** 开关被显式关闭，**When** 访问管理路径，**Then** 返回"资源不存在"，接口不生效。

---

### Edge Cases

- **删光条目后重启**：不得重新导入配置文件条目（US2 场景 2 的反面），这是本 feature 最容易被实现错的一点。
- **配置文件本身为空**：首次启动的导入会写入 0 条，但"已导入"这一状态必须被记住，否则每次启动都被当作"从没导入过"。
- **并发重复新增**：两个请求同时提交同一 `(类型, 值)`，只允许一条成功，另一条得到冲突错误而非数据库异常泄漏到响应体。
- **并发修改与校验**：工具正在执行校验时运营方删除了条目，一次校验只允许看到一致的策略快照，不允许"看到一半新一半旧"。
- **非法输入的错误信息**：不得把调用方输入的原始值回显到响应里（同源管理台渲染时是注入面）。
- **等价但未被归一的写法**：同一路径在不同平台的大小写差异不强行改写，属于已知边界，需在文档中明示。
- **关闭开关后重启**：关闭期间条目仍保留在库中，重新开启后应恢复生效，不得因关闭而清空数据。
- **条目数量上限**：列表不分页，需有成文的上限与超限行为，避免无界增长。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供白名单条目的新增、查询（列表 + 单条）、修改、删除五类操作，且改动**立即生效**，无需重启进程。
- **FR-002**: 系统 MUST 将条目持久化，进程重启后条目与运行时策略均从持久化状态恢复。
- **FR-003**: 系统 MUST 以持久化状态作为运行时事实源；配置文件中的白名单只在**首次启动**时导入一次，之后配置文件变更不影响运行时（除非显式重置）。
- **FR-004**: 系统 MUST 用独立于条目数据的持久化标记记录"已导入"状态，使「导入过 0 条」与「从未导入」可区分。
- **FR-005**: 系统的校验路径 MUST 以无锁方式读取一致策略快照；单次校验内不得看到跨版本的混合策略，且校验路径不得引入阻塞锁。
- **FR-006**: 系统 MUST 对三类值分别执行格式校验与归一化；归一化必须幂等，且归一后的形态同时作为存储形态、判重形态与返回形态。
- **FR-007**: 系统 MUST 对等价的文件路径写法归一到同一形态，使唯一性约束真正生效（判重不被等价写法绕过）。
- **FR-008**: 系统 MUST 只接受 ASCII 域名，非 ASCII 域名被拒绝并提示改用 punycode 形式。
- **FR-009**: 系统 MUST 在重复新增同一条目时返回冲突错误，而非静默覆盖。
- **FR-010**: 系统 MUST 在修改时保持条目类型不可变；需要换类型时以删除 + 新增表达。
- **FR-011**: 系统 MUST 在查询不存在标识时返回"不存在"错误。
- **FR-012**: 系统的错误响应 MUST 不包含调用方输入的原始值；须说明字段与违反的规则。
- **FR-013**: 系统 MUST 通过一个配置项控制管理接口启用与否，默认启用；关闭后该接口不可访问且返回"资源不存在"。
- **FR-014**: 系统 MUST 在管理接口启用时于启动日志输出显式安全告警。
- **FR-015**: 系统 MUST 对每次增删改记录一条可追溯的操作日志，含链路标识、操作类型、条目类型与标识；日志中的用户可控字符串须做换行净化；不得记录说明字段全文。
- **FR-016**: 系统 MUST 保证 Windows / macOS / Linux 上行为一致，并在持续集成中对三平台运行同一组规则测试。
- **FR-017**: 系统 MUST 保持既有沙箱接口与工具侧校验调用点不变；本 feature 只允许在实现内部增加策略刷新能力。
- **FR-018**: 系统 MUST 对列表查询定义条数上限及超限行为，不提供分页。**每类上限 1000 条，超出返回 400。**
- **FR-019**: 系统 MUST 在首次导入配置文件条目时先归一化再入库；**任何一条非法或无法归一的配置值都 MUST 使该次启动失败并明确指出是哪一条**，不得静默跳过或原样存入。
- **FR-020**: 系统 MUST 在修改条目导致归一后新值与该类型其他条目重复时返回冲突错误，**且保持该条目原值不变**（不做自动合并）。

### Key Entities

- **白名单条目**：一条生效规则。属性：标识、类型（文件路径 / 命令 / 域名，三选一且不可变）、值（归一后）、可选说明、创建时间、更新时间。同一类型下值唯一。
- **导入标记**：单条记录，表示"配置文件已导入过"。属性：导入时间、本次导入的条目数（可为 0）。与条目数量无关，仅存在即代表已导入。
- **策略快照**：某一时刻生效的三类规则集合，由条目重建而来，供校验路径只读使用；整体替换，不原地修改。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新增或删除一条白名单后，下一次工具调用即体现新策略；运营方不需要重启进程，改动生效时延在一次工具调用之内。
- **SC-002**: 进程重启后，接口维护的条目 100% 保留，且删空条目后重启的复现率为 0（不重新导入配置文件）。
- **SC-003**: 三类值的非法输入全部被拒绝并给出可操作的规则说明；错误响应中 0 处出现调用方原始输入。
- **SC-004**: 同一路径的 5 种等价写法在系统中只存在 1 条记录，第 2~5 次提交均返回冲突。
- **SC-005**: 三平台（Windows / macOS / Linux）持续集成上同一组规则测试与校验测试全部通过。
- **SC-006**: 全部质量门禁通过（格式、编码规约、静态分析、安全扫描），无需放宽任何阈值。

## Assumptions

- 核心阶段为单二进制单实例部署，不做多实例快照同步；多实例一致性属扩展阶段。
- Web 服务核心阶段无认证（`TechnicalSolution.md` §7.5），管理接口的安全性由部署方式（回环绑定 / 认证反向代理）承担。
- 运行时校验沿用既有的应用层白名单实现与其校验语义（相对路径按进程当前工作目录解析），本 feature 不改变校验算法。
- 管理台不在本 feature 范围内；本 feature 只交付接口，管理台按接口契约对接。
- 三类白名单之外无其他动作类型（SMTP 端点归扩展阶段）。
- 条目为低基数配置，列表不分页是可接受的取舍；每类上限固定为 1000 条，超出按参数错误拒绝。
- 既有数据库迁移编号顺延，Windows / macOS / Linux 上迁移脚本可在空库从零执行。
- 配置文件首次导入采用「严格模式」：归一化失败即启动失败，宁可起不来也不静默吞掉脏配置。
- 管理接口开关的配置键为应用级命名空间（`sableos.sandbox.admin.enabled`），与配置文件中既有的根级 `sandbox.*` 键并存；后者属早期遗留，不在本 feature 内调整。

## Clarifications

### Session 2026-10-29

- Q: 首次导入时 YAML 里有非法或非归一的值怎么办？ → A: 归一后导入；任一条非法则整次启动失败，并指出是哪一条（FR-019）。
- Q: 每类条目上限？ → A: 1000 条，超出返回 400（FR-018）。
- Q: 配置键用 `sableos.sandbox.admin.enabled` 还是根级 `sandbox.admin.enabled`？ → A: 维持 `sableos.sandbox.admin.enabled`（应用级命名空间），根级 `sandbox.*` 为既有遗留不在本节调整（FR-013）。
- Q: 修改条目撞重复时怎么办？ → A: 返回 409 冲突并保持原值不变，不做自动合并（FR-020）。
